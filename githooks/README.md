# githooks

커밋 직전에 도는 검사들. `.git/hooks` 는 깃이 추적하지 않아 클론하면 사라지므로 여기에 두고 추적한다.

## 설치 (클론마다 한 번)

```bash
git config core.hooksPath githooks
```

**설정 자체는 추적되지 않는다.** 새로 클론했거나 훅이 안 도는 것 같으면 이 한 줄을 먼저 확인한다.

```bash
git config --get core.hooksPath      # githooks 가 나와야 한다
```

연결된 워크트리(`git worktree`)에는 따로 설정할 필요가 없다. 설정이 저장소 전체에 걸리고, 경로는 각 워크트리의 루트 기준으로 풀린다.

## pre-commit

두 가지를 막는다. 배경은 저장소 루트의 `AGENTS.md` 에 있다.

| 막는 것 | 왜 |
| --- | --- |
| 기본 브랜치(`main`)에 직접 커밋 | PR 없이 프로덕션 경로로 나간다. 2026-07-29 에 남의 체크아웃에 얹혀 실제로 벌어졌다 |
| 이미 머지됐고 뒤처진 브랜치 위에서 커밋 | 그 상태의 수정분은 새 작업이 아니라 **되돌리기**다. 2026-07-31 에 22파일 766줄이 되돌아갈 뻔했다 |

두 번째 검사는 **자기 커밋이 하나도 없는 브랜치에만** 걸린다. 커밋이 하나라도 있으면 `origin/main` 의 조상이 아니게 되어 통과한다. 그래서 진행 중인 작업을 인질로 잡지 않고, 걸렸을 때는 브랜치를 다시 따도 잃을 게 없다.

`origin/main` 이 로컬에 없거나 낡았으면 검사는 조용히 통과한다(fail-open). 커밋을 막는 쪽보다 낫다고 보고 그렇게 뒀다.

정말 필요하면 `git commit --no-verify` 로 넘어갈 수 있다.
